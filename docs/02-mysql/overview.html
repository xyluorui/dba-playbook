0. 总览：一条 SQL 的旅程

客户端 → Server 层 → 存储引擎层 → 文件系统

  • Server 层负责连接管理、认证与 SQL 处理。语句依次经过解析、预处理、优化和执行。MySQL 8.0 已移除查询缓存。
  • 存储引擎层：插件式，InnoDB（默认）/ MyISAM / Memory
  • 文件层：表空间文件、redo log、undo log、binlog

1. Server 层

详细内容：sql-execution-and-explain.html

  • 连接管理涉及认证、线程模型和 max_connections。
  • 解析：词法分析、语法分析、AST
  • 优化器：基于成本（CBO）、统计信息、索引选择、join 顺序、optimizer_trace、优化器 hint
  • 执行器：调用存储引擎接口、逐行返回
  • 执行计划：EXPLAIN / EXPLAIN ANALYZE，关键列 type / key / rows / filtered / Extra
  • 常见执行方式：索引覆盖、回表、Filesort、临时表、ICP（索引下推）、MRR、BKA

2. 存储引擎：InnoDB 架构

2.1 内存结构

  • Buffer Pool：数据页缓存、LRU（young/old 分区）、Free / Flush / LRU 链表、预读（线性 / 随机）、脏页与刷脏、多实例
  • Change Buffer：非唯一二级索引的变更缓冲
  • Adaptive Hash Index：自适应哈希索引
  • Log Buffer：redo 日志缓冲

2.2 磁盘结构

  • 表空间：系统表空间（ibdata）、独立表空间（.ibd）、通用表空间、undo 表空间、临时表空间
  • 数据组织：表空间 → 段（Segment）→ 区（Extent，1MB）→ 页（Page，16KB）→ 行
  • 页类型：数据页、索引页、undo 页、Change Buffer 页等
  • 行格式：Compact / Redundant / Dynamic / Compressed，溢出页（off-page）
  • Doublewrite Buffer：防部分写（torn page）

2.3 后台线程

  • Master Thread、IO Thread、Purge Thread、Page Cleaner Thread

3. 索引

  • 数据结构：B+ Tree（为何不是二叉树 / B 树 / 哈希）、Hash 索引、全文索引、空间索引
  • 分类：
    • 物理：聚簇索引（主键）、二级索引（非聚簇）
    • 逻辑：主键、唯一、普通、联合、前缀、函数 / 表达式索引
    • 8.0 新增：降序索引、不可见索引
  • 概念：回表、覆盖索引、最左前缀、索引下推（ICP）、索引选择性、索引失效场景
  • 主键选择：自增主键 vs UUID、页分裂与页合并、填充因子
  • 统计信息：基数（cardinality）、ANALYZE TABLE、采样

4. 事务

4.1 ACID 与实现手段

特性主要保证机制
原子性 Atomicityundo log
持久性 Durabilityredo log + 刷盘策略
隔离性 Isolation锁 + MVCC
一致性 ConsistencyA + I + D + 约束

4.2 事务隔离级别

  • 读未提交 / 读已提交（RC）/ 可重复读（RR，默认）/ 串行化
  • 并发问题：脏读、不可重复读、幻读
  • 快照读 vs 当前读

4.3 MVCC

  • 隐藏列：DB_TRX_ID / DB_ROLL_PTR / DB_ROW_ID
  • undo 版本链、Read View（m_ids / min_trx_id / max_trx_id / creator_trx_id）
  • RC 与 RR 的 Read View 生成时机差异
  • purge：历史版本清理、长事务危害

4.4 事务控制

  • 自动提交、BEGIN / COMMIT / ROLLBACK、保存点（SAVEPOINT）
  • 事务状态：活跃、提交、回滚、XA（两阶段事务）、分布式事务

5. 锁

  • 粒度：全局锁、表锁（表级 S/X、意向锁 IS/IX、自增锁 AUTO-INC）、元数据锁（MDL）、行锁
  • InnoDB 行锁类型：
    • Record Lock（记录锁）
    • Gap Lock（间隙锁）
    • Next-Key Lock（临键锁 = 记录 + 间隙）
    • Insert Intention Lock（插入意向锁）
  • 模式：共享锁（S）/ 排他锁（X）、乐观锁 / 悲观锁
  • 加锁规则：与隔离级别、索引类型（唯一 / 非唯一 / 无索引）、等值 / 范围查询相关
  • 死锁：产生条件、死锁检测（wait-for graph）、innodb_lock_wait_timeout、SHOW ENGINE INNODB STATUS
  • 元数据锁（MDL）：DDL 阻塞、Online DDL（INPLACE / COPY / INSTANT）

6. 日志体系

日志层级作用形式
redo logInnoDB崩溃恢复（持久性）物理日志，循环写
undo logInnoDB回滚 + MVCC逻辑日志
binlogServer归档、主从复制、PITR逻辑日志，追加写
relay logServer从库中继日志同 binlog
error logServer错误 / 启动信息文本
slow query logServer慢 SQL文本
general logServer全量语句文本
  • redo：WAL、LSN、Checkpoint、innodb_flush_log_at_trx_commit
  • binlog：格式（STATEMENT / ROW / MIXED）、sync_binlog、GTID、binlog 事件
  • 两阶段提交：prepare → binlog write → commit，保证 redo 与 binlog 一致
  • 组提交（Group Commit）：flush / sync / commit 三阶段
  • 崩溃恢复流程

7. 复制与高可用

  • 主从复制原理：binlog dump 线程 → IO 线程 → relay log → SQL 线程
  • 复制模式：异步、半同步（after_sync / after_commit）、组复制（MGR）
  • 复制方式：基于位点、基于 GTID
  • 并行复制：基于库 / 组提交 / WRITESET / LOGICAL_CLOCK
  • 复制延迟：成因与治理
  • 高可用方案：主从 + 切换、MHA / Orchestrator、MGR、InnoDB Cluster、中间件（ProxySQL / MySQL Router）
  • 读写分离：数据一致性问题

8. 查询优化

  • 慢查询：slow_query_log、long_query_time、pt-query-digest
  • 分析工具：EXPLAIN、optimizer_trace、SHOW PROFILE、performance_schema、sys schema
  • 常见优化点：索引设计、SQL 改写、分页（深分页）、join、子查询、ORDER BY / GROUP BY / DISTINCT、COUNT(*)
  • Join 算法：Nested Loop、Block Nested Loop、Hash Join（8.0.18+）、BKA
  • 排序：sort buffer、单路 / 双路排序、max_length_for_sort_data
  • 临时表：内存 / 磁盘临时表
  • 分区表、分库分表（水平 / 垂直）及其代价

9. 数据类型与表设计

  • 数值 / 字符串 / 时间 / JSON / 空间类型选择
  • 字符集与排序规则：utf8mb4、collation、乱码成因
  • 范式与反范式、主键设计、NULL 的影响
  • 约束：主键、外键、唯一、检查约束（8.0.16+）
  • 生成列、视图、存储过程 / 函数 / 触发器 / 事件

10. 运维与管理

  • 权限与安全：账号、角色（8.0）、权限层级、认证插件、SSL、审计
  • 备份恢复：逻辑备份（mysqldump / mydumper）、物理备份（XtraBackup）、增量备份、PITR（全量 + binlog）
  • 参数体系：全局 / 会话变量、持久化（SET PERSIST）、关键参数（buffer pool、redo、flush、连接数）
  • 监控：SHOW STATUS、information_schema、performance_schema、sys、SHOW ENGINE INNODB STATUS
  • 在线 DDL 与大表变更：gh-ost / pt-osc
  • 升级迁移：版本差异（5.7 → 8.0）、数据迁移与校验
  • 容量规划、连接池、典型故障：连接打满、主从延迟、死锁、长事务、磁盘满、OOM
